# 第七轮（2026-10-10）：第二份 Windows 测试报告的跟进，合并队友两个分支，复查修 bug

## 由来

宗涛在 Windows 上测了第六轮的 `0ec3619`（2026-10-10 报告）：启动、答疑、出处、闪卡、整卷、模型登记都走通，
列出的问题有：整卷大题的逐句批注刷新后丢失；前端格式与 ESLint 检查不过；依赖审计有高危；
启动时参考文献那一步的中文是乱码；一篇论文下载 404 时看不出缺的是哪篇；Docker Desktop 又出过故障。

队友已经推了两个分支：
- `fix/windows-report-followups`（FDD）：全仓 prettier 格式化、清 ESLint、整卷批注刷新后保留、笔记本来源下载失败的标记、依赖审计处理（去掉 `xlsx`，其余用 overrides 升到修过的版本）。
- `integrate/verified-rag-20261010`（宗涛）：透传流解压、流末尾只带用量的块不再抹掉结束原因、
  版本化的本地索引缓存（不再反序列化 pickle，按嵌入模型的实际版本区分）、同一个问题 60 秒内复用检索结果。

随后又合并了 `feature/ui-polish`（文娜，10-06，基于第六轮之前的版本），见下面「文娜的界面改动」。

## 合并前逐个审

- 两个分支都从 `0ec3619` 出发，一个只改前端、一个只改后端，合并无冲突。
- FDD 的批注修法：完成了的批注随整卷存档一起存，进行中、失败的不存（免得刷新后永远「加载中」），旧存档照样能读。
- 宗涛的两处流式修复都对：透传原样转发了压缩过的字节却没转发压缩头，客户端解不开；
  上游最后如果多发一个只带用量、结束原因为空的块，原来的写法会把前面的 `stop` 抹掉，
  正常答完的回答末尾被误加「回答中断」。
- 宗涛的索引缓存实测（本机真实模型）：能读出模型的实际版本（commit `183bb99…`），磁盘缓存生效；
  升级后第一次启动旧缓存不再用、全部重新嵌入，39 秒；第二次启动 5 秒。旧格式的缓存（约 20MB）他选择保留不删，
  方便退回旧版本。

## 复查查出、这一轮修的

1. **一条旧对话就能让整个答疑页崩掉（FDD 的 lint 改动引入）。** ESLint 要求列表循环带 key，
   话题标签和追问建议被改成用文字本身当 key；而标签生成时没去重（「排队 排队 是什么」会出两个「排队」），
   浏览器里存着的旧对话也可能已经有重复标签。Svelte 正式版遇到重复 key 也会抛错（`each.js` 351–356 行），
   实测：塞一条带重复标签的旧对话，刷新后整个答疑页渲染失败、对话列表全空。
   改成标签生成时去重，渲染时 key 带上序号；设置里「添加连接」的模型 ID 同理（同一个 ID 可以加两次）。
   其余用文字当 key 的地方查过，数据本身不会重复（提示词标签合并前用 Set 去过重、编辑器添加时查重、表情和快捷键是写死的列表）。
2. **启动时参考文献那一步乱码。** 外部程序接管 `start.bat` 的输出时，如果先把窗口改成了 UTF-8，
   PowerShell 自己的提示按 UTF-8 写，Python 却按系统代码页（GBK）写，只有这一段是乱码。
   这一步改为让 Python 用 PowerShell 当前的输出代码页（`PYTHONIOENCODING=cp<代码页>:replace`），用完恢复原值；
   直接显示在窗口上时 Python 走控制台接口，不受影响；写不出的字符替换成问号，不会因为编码让这一步失败。
3. **下载失败看不出缺了哪篇。** 原来是英文异常原话加「1 篇失败（见上）」。现在汇总后逐篇点名，原因说成人话
   （「官网返回 404」「下载超时」），没下到原文的注明「下次启动会再试」，并说明答疑、出题照常用教材和其余论文。
   那次 404 是期刊网站临时出错：14 篇的地址现在都能正常下载。
4. **第一次启动日志说「向量索引缓存无效」。** 其实只是这一版还没建过缓存。改成没建过时不出声；
   已经有缓存却读不进来（文件不全、被改过、和现在的材料对不上）时一律说一声再重建——原来校验不过的几种情况是悄悄重建的。
5. FDD 新加的整卷存档单测里，试卷字段 `essay` 拼成了 `enessay`，改正。

## 文娜的界面改动（`feature/ui-polish`）

内容：输入框打 `#` 选笔记本、打 `@` 选模型（和顶栏两个选择器效果一样）；提示词菜单原来放在会裁剪内容的滚动区里，看不见，挪到外面；
「提问」「解释」挪进回答下方的操作栏并加了图标；用选中文字发起的提问，气泡里把引用部分画成「▎灰字」一行，
发给模型的仍是原文（`requestContent`），重新生成也用原文；文件夹弹窗去掉只在本地生效的「上传文件」，改成引导去笔记本；
欢迎页换了比赛名称，网站图标、知识库按钮、追问按钮改小。

她的分支在 FDD 全仓格式化之前，6 个文件冲突。输入框那份 git 对错了位置（旧布局留在前面、只在后面标了冲突），
改为在第六轮的版本上按她的改法重做：菜单移出滚动区、加 `#`/`@` 菜单。选择智能体页的底栏保留第六轮的「登记 / 管理模型」入口，
状态说明按她的意思只在读不到模型时出现。

复查查出、顺手修的：
1. 「提问」「解释」挪进操作栏后，窄一点的窗口（例如侧栏打开时内容区只有三百多像素宽）放不下，
   「加入笔记本」被挤成三行、两个按钮竖着叠。改成操作栏整组换行、按钮文字不折行。
2. 选中的是好几行时，气泡只把第一行画成灰色引用，后几行混进提问里。显示时把引用部分并成一行（发给模型的原文不变）。
3. 操作栏里新加的按钮循环没有 key、一个变量赋了值没用上，`npm run lint` 不过，补上。

另外发现：样式表里有一条不在层里的 `button, input, select, textarea { font: inherit }`（2026-09-10 交接包里就有），
它压过了 Tailwind 的字号类，所以所有按钮、输入框上写的字号、字重、行高都不生效、一律跟随外层。
文娜把追问按钮改成 8px 因此看不出变化。见下一节，已修。

## 按钮字号类不生效（全站）

Tailwind 自带的基础样式（base 层）本来就有同样的 `font: inherit`，层里的规则会被字号类正常覆盖；
`src/app.css` 里多出来的这条不在层里，层外的样式压过所有层，于是字号类全部失效。删掉这条，其余（点按高亮、光标、盒模型）不动。

逐页核对改了什么：改之前按钮、输入框一律跟随外层，所以改之后凡是和外层不一样的，就是这次改出来的。
在 1280×800 下逐页列出来、截图看过：答疑（课程 / 论文两种模式）、整卷（作答、结果）、闪卡（填空、选择）、笔记本、模型登记、
选择智能体、欢迎页、设置面板（通用、界面）、用户菜单、工作区。变化都是类上原本写的尺寸——题号小块 16→12px、
侧栏小标题 14→12px、输入框 16→14px、论文任务卡的输入框 12px、「从笔记本选择笔记」11px、知识库小按钮 10px 等，
没有溢出、折行异常；手机宽度下没有横向滚动。

唯一需要改的是追问按钮：文娜写的 8px 真生效后看不清，改成 12px（和操作栏文字一样），保留她的浅色小胶囊样式。

## 留给以后

- 本轮 `start.ps1` 的改动仍要请队友在 Windows 上复测。
- 外部程序重定向 `start.bat` 时，后台启动的子进程会继承输出管道，读输出的一方要等它们退出才读得到结尾（报告第 4 条后半）。
  这只影响测试工具，正常双击启动不受影响，这一轮没改。
- 旧格式的向量缓存不会自动清理，以后确定不再退回旧版本时可以手动删掉。
- 笔记本为空时打 `#` 没有任何反馈；以后可以显示一句「还没有笔记本」。
- 手机宽度下侧栏沿用电脑上的展开状态，展开时把对话挤成很窄一列（这次之前就这样，和字号修复无关）。

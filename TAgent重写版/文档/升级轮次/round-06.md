## 结果

### 1 启动脚本（`scripts/start.ps1`）
- `Start-Process -PassThru` 之后马上 `$null = $buildProc.Handle`。不取一次句柄，进程结束后 `ExitCode` 是空值，
  拿空值比 0 就把成功的构建判成了失败。
- 三处 `Get-Content` 读 `.env.runtime` 加 `-Encoding UTF8`（写入时一直是无 BOM 的 UTF-8）。
- 启动后端前设 `PYTHONUTF8=1`：后端输出被重定向到 `logs\runtime\*.log`，中文 Windows 上 Python 写重定向文件默认用 GBK。
  只在启动后端那一步设（见第 7 条）。
- 本机没有 PowerShell，这三处没能在 Windows 上实跑，要请队友复测。

### 2 思考模型的输出额度（`app/infra/llm_json.py`）
- 被截断后下一次尝试把 `max_tokens` 加 4096（封顶 8192）；仍被截断报「模型的输出被截断了：……可在模型登记里关闭思考」，
  不再笼统地报「输出结构异常」。截断之后那次是别的失败（调用出错、JSON 不对），照旧报原来的原因。
- **顺带查出**：langchain 的 `ChatOpenAI` 把 `max_tokens` 改名成 `max_completion_tokens` 发出去，
  而 DeepSeek 只认 `max_tokens`。用本机登记的 DeepSeek 实测：`max_tokens=8` 截在 8 个 token；
  `max_completion_tokens=8` 照常写了 96 个。所以**在 DeepSeek 上，各处给出题、批改定的输出额度其实一直没生效**，
  也就不会被截断。认这个参数的上游（OpenAI 等）才会截断，加额度重试是为它们准备的。没有改成强制发 `max_tokens`：
  那些额度从没在 DeepSeek 上真正生效过，比赛前突然生效，可能把原本完整的输出截断。

### 3 模型登记的「附加参数」（`extra_body`）
- 登记时可填一个 JSON 对象，原样并进每次请求体：答疑、出题、批改（`ModelClientFactory`）和给 OpenNotebook 用的透传通道都带上
  （透传时调用方自己写了同名字段的，以调用方为准）。
- 主要用来关闭思考，各家写法不同：DeepSeek / 智谱 / 豆包 `{"thinking": {"type": "disabled"}}`，通义千问 `{"enable_thinking": false}`。
  所以做成自由填写的参数，没做成一个开关。
- 校验：必须是对象；不能改 `model`、`messages`、`max_tokens`、`temperature`、`stream` 等由系统决定的字段；JSON 不超过 2000 字符。
  以前登记的模型没有这个字段，读进来按空处理，不用迁移。

### 4 回答带出处（`app/rag/citations.py`）
- 检索到的材料本来就原样放进了 prompt，现在同一批材料摆成出处随回答返回：
  - 流式：检索完、第一段文字之前单独发一帧，`delta` 为空、顶层带 `citations`。别的 OpenAI 兼容客户端照常跳过这一帧。
  - 非流式和 `/rag/query`：响应里多一个 `citations`。
  - 出处不混进 `stream_answer` 的产出（别处都按「(文字, 结束原因)」两元组读），改由回调交给接口层。
- 三种材料：
  - 教材：第几章、第几页。`book1.md` 是逐页转写的，页标记 `--- Page N ---` 比书上印的页码大 1
    （第 1 页是空白的打印封面，文中「页码信息」写着印刷页码，从头到尾抽查十几处都差 1），按印刷页码给。
    章号取一到三级标题里的「第 N 章」或打头的小节号，图表编号、四级标题里的数值（「步长为 0.01」「10.53 秒」）不算。
    实测 2178 块里 2174 块定位到了，1→9 章依次出现、页码单调递增。
  - 论文：题目、期刊卷期页、期刊官网文章页的链接（只认 http/https）。
  - 笔记本：来源 / 笔记 ID，前端按它对回笔记本。
- 同一页教材、同一篇论文只列一次。教材块的元数据变了，索引缓存格式随之改名，第一次启动会重建索引；
  块向量有缓存，不用重新嵌入。
- 前端：后端给的出处标成「回答确实用到的」，不再按问题的字面相关度筛掉；论文新窗口打开官网，教材没有可打开的页面就不做成链接；
  悬停显示片段；「加入笔记本」导出时论文附上网址。

### 5 网页登记模型（`/models`）

### 7 复查（review）查出的
1. 认不出种类的材料被当成了教材：出处模块原来把没有 `source` 标记的材料一律算作「课程教材」，
   而 OpenNotebook 对少数怪格式的检索结果建的材料就没有这个标记。改成教材块明确标 `source = textbook`，
   认不出的不列（OpenNotebook 那条也补上了标记）。
2. `PYTHONUTF8` 原先在「载入环境变量」就设了，参考文献那一步的 Python 也会受影响。它的输出直接进命令窗口，
   万一被 PowerShell 接管（PowerShell 按 GBK 解码），就会从正常变成乱码，修一处坏一处。改成只在启动后端那一步设。
3. 「试一下」没有超时：上游卡住时按钮要「正在试…」挂满后端 180 秒。改成 60 秒就停并说明。
4. 「删除」点过一次没确认、又去做别的操作，按钮一直停在「再点一次确认删除」，之后随手一点就删了。改成做别的操作就取消待确认。
5. 存进笔记本时，教材出处写成「课程教材 · 课程教材 · 第3章 · 第71页」，改成只写一次。

第 3、4 条在浏览器里复测过（假模型设成卡住，60 秒时出现提示；点过「删除」再点「设为默认」，删除按钮恢复原样）。

# 第五轮（2026-10-03）：范例入库、《系统仿真学报》参考文献接入检索、笔记本连不上的根因、开机后同时提问会崩

## 由来

- 「samples 也要 push 到远程，因为其他人用的时候也要」：答疑「填入范例」的范例原先一律不入库。
- 「系统仿真学报里面的东西也要作为一个参考用来评分 / 出题」「你能不能直接下载进去」「是不是点击 start 脚本就会自动下载」。
- 「能不能把 rag 启动也加入 start 脚本里面」：检索（basic-agent）本来就由启动脚本拉起，追下去发现
  启动时打印的「笔记本连不上」是真问题，见下面第 3 条。
- 「review 一遍，检查一下所有的东西」「还有连点那些暴力测试」「还要优化速度」：见第 4、5 条。

## 计划（开工时）

1. 范例：自己写的入库共用，别人的文章不能进公开仓库。
2. 参考文献：放进后端本地知识库（和教材一起用自己的嵌入模型建索引），出题、答疑、批改的检索都用得上；
   仓库是公开的、论文版权在期刊（官网写「版权所有 © 北京仿真中心 中国仿真学会」，没有开放许可），
   所以**仓库里只放篇目清单**，全文由启动脚本从期刊官网下到每个人本机。先下 14 篇。
3. 判据：后端每条修复配测试并扰动；真实嵌入模型下检索命中论文；启动脚本测试通过；全文不出现在仓库里。

### 3 笔记本一直连不上：系统代理
- 现象：OpenNotebook 开着、`curl` 直接访问 5055 正常，basic-agent 的健康检查却一直失败，`notebook_reachable = false`，
  笔记本里的内容从来没进过检索。
- 根因：basic-agent 进程环境里没有代理变量时，httpx 会去读 **macOS 的系统代理**（开着 Clash 的电脑就是 127.0.0.1:17897），
  连 `http://localhost:5055` 也送进代理，代理回 502。终端里因为有 `NO_PROXY=localhost` 所以试不出来。
- 修法：OpenNotebook 地址是本机或局域网（回环、私有网段、`.local`）时不读系统代理，直连。模型客户端早就是这么做的，笔记本这条漏了。

### 6 论文里的表格和公式（「论文里抽出来的表格和公式是乱的，要怎么处理」）

| 做法 | 适用 | 结果 |
|---|---|---|
| A. 抽 PDF 时清洗：表格整块换成一行「（原文表 N：表题，涉及：表里的中文项目名称，数据见原文）」；连续 3 行以上的短碎片（行间公式被拆成的「Δps」「=」「ì」、一格一行的单元格）去掉；带式号的整行公式、没有中文的数字行去掉；图题单独成段；单独成行的引用编号先去掉 | 14 篇 | 疑似乱码的文字占比 5.2% → 0.03%；纯中文分句 2866 个，新版只少了 3 个，都是机场那篇表格里的格子 |
| B. 有网页版全文的改用网页版：表格转 Markdown 表格，MathML 公式转 LaTeX，HTML 上下标转 `X_{ijk}`，图只留图题；网页版取不到或认不出就退回 PDF，只是没下到的下次启动再试 | 3 篇（2022 年以后） | 表格行列完整（如 6×6 的机器距离表、11 列的实验参数表），公式 300 多个 |
| 检索：论文每块 800 字照旧返回，但用 200 字的小窗口去匹配 | 14 篇 | 见下表 |

最后一行是测出来的：做完 A、B，12 道手写题第一条找对反而从 11 掉到 9——检索只看每块前一百二十来个字，
文字一变块的开头就变。换成小窗口匹配后：

| 题目（只在论文之间比，和线上一样按欧氏距离） | 改之前 | 改之后 |
|---|---|---|
| 12 道手写题：第一条 / 前三 | 11 / 12 | 12 / 12 |
| 112 道正文句子题（每篇 8 句、新旧两版都有的句子）：第一条 / 前三 | 79 / 96 | 92 / 104 |
| 3 道只有表格里才有的题：第一条 / 前三 | 2 / 2 | 2 / 2 |

块大小试过 800、400、300、200、150：越小越准，200 与 150 相当，取 200（窗口少，建索引快）。
试过把表格窗口里的竖线换成顿号再匹配，三组题结果一模一样，没留。
按主题出卷时 MMR 的候选池仍是 20（压测定的），只多挑一倍备用：按顺序挑，前 10 个与以前相同。
代价：第一次建索引的条目从 2400 多条变成 3300 多条（多出来的是论文的小窗口），本机从 0 建约多二十秒，之后照旧走缓存。

## 留给以后
- `start.ps1` 加了同样的步骤，本机没有 PowerShell，**没在 Windows 上跑过**。
- 本机 OpenNotebook 没配嵌入模型：笔记本检索退回关键词检索。要语义检索得在 OpenNotebook 里配 embedding。
- 选了某个笔记本时只查那个笔记本（教材和参考文献都不查），这是原有约定；选「全部笔记本」时三路一起查。
- PDF 里的表格和公式抽出来是乱的，检索时只当上下文，不影响用。
- 英文正文的那篇（交叉口掉头）用中文嵌入模型检索效果一般。
- 嵌入模型只读每块前 128 个字，而教材是按 800 字切的：每块后面的内容向量检索看不到。这是原有设计，改切块大小会牵动整个检索，没在这一轮动。
- `deploy/` 下的开机自启服务直接起 basic-agent，不经过启动脚本，所以不会自动下载论文；需要时手动跑一次 `tools/fetch_references.py`。

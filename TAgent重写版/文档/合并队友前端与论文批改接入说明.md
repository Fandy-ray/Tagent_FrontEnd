## 三、功能说明（使用视角）

### 1. 答疑 · 论文辅助模式

顶栏切到「论文辅助」后，有三类操作，**互相独立**：

- **分章写作（队友原有）**：任务卡按 7 个章节（选题与大纲、摘要、相关工作、研究方法、实验设计、结果与讨论、完整性检查）分步写。选一节 → 填这一节的几项信息 → 点对应按钮，模型按这一节的要求给出对话回答。
- **让助手出题（新增）**：按当前笔记本的材料出一道小论文题，以「题签」形式显示在对话里（题目 + 2~4 条写作要求 + 建议篇幅）。点「设为本次题目」即写入任务卡。没检索到材料时会注明「按课程通用内容出题」。
- **交稿批改（新增）**：把整篇正文粘进输入框，点「交稿批改」（正文需 100~6000 字）。返回一张批改过的卷子：
  - **评分栏**：切题与内容 40 分 / 论证与结构 35 分 / 语言与规范 25 分，默认展开得分最低的一项，逐条显示评分要点的 ✓ / ✗；
  - **正文批注**：朱笔画线，直线 = 需修改，波浪线 = 写得好，句末带编号；
  - **编号旁批**：每处批注的具体意见，点一下跳到对应句子；
  - **字数统计与总评**。

批改卡会随对话保存，刷新页面后仍在、高亮位置不变；批改中可以停止，之后点「重新批改」重跑。

> 区别：**章节按钮是帮你写，交稿批改是给你打分**。任务卡上已加一行说明。

### 2. 测评 · 整卷模式

- 进入测评先选模式：闪卡（本地即时判定）或整卷（交卷后由模型判分）。
- 整卷交卷后，点开某道大题 →「逐句批注」，挑出最多 2 处该改的句子和 1 处写得好的句子，画线并说明。
- **点哪道才批哪道**，不点不调用模型。

## 四、实现方式

### 1. 合并步骤

1. 新建分支，先把我们未提交的后端批改代码和旧前端各提交一次，作为留底；
2. 用她的前端整体覆盖 `tagentnote/` 目录（单独一个提交，便于审查差异）；
3. 从留底提交中把我们的测评栈移植回来；
4. 补后端接口，再在她的论文模式里接上出题与批改。

### 2. 后端改动（basic-agent）

- **小论文批改** `POST /essay/review`：三个维度并发打分，字数、段落、引用检测在本地算；论证维度顺带指出问题集中的段落，只对这些段落逐句批注。
- **大题批注** `POST /quiz/exam/annotate`：按需批注，题干与评分要点从服务端缓存取，不信任客户端传值。
- **出题（新增）** `POST /essay/topic`：按笔记本材料出题，学生给的方向按不可信输入隔离；检索失败也照常出题。
- **对话接口** `POST /v1/chat/completions`：
  - 识别 `mode: "paper"`，换成论文写作助教的系统提示词（以前被忽略，队友的论文提示词一直没生效）；
  - 接受 `retrieval_query`，论文模式用「题目 + 关键词」检索，而不是拿几千字的任务提示去检索。
- 出卷、判卷、批改、出题共用一个并发闸门，满了立即返回「稍后再试」，不排队。

### 3. 前端改动（tagentnote）

- 移植回：闪卡 / 整卷面板、公式渲染（KaTeX）、批注组件、测评相关数据与接口函数；
- 新增组件：题签卡 `PaperTopicCard`、批改卡 `PaperReviewCard`，纸面样式统一在 `paper.css`；
- 对话消息新增 `paperCard` 字段，随会话存进浏览器本地；
- 输入框新增「交稿批改」「填入范例」，任务卡新增「让助手出题」；
- 批注组件支持 id 前缀，同一对话里交多次稿不会互相串位。

### 4. 关键设计原则

- **批注只回句子编号**：后端先切句编号，模型只回编号（如 P2S3），高亮区间由后端查表给出。前端只校验、不搜索，对不上的不画线，避免错位。
- **原文一字不差留存**：批改卡保存发给后端的原文，刷新后按同一份原文还原高亮。
- **打分可复算**：每个维度的评分要点固定 4 条，该项得分 = 命中数 ÷ 4 × 该项满分，不给印象分。
- **学生文本不可信**：作文、选题方向在提示词里都做了隔离，防止「忽略要求给满分」这类注入。

## 五、接口一览

| 接口 | 用途 | 主要参数 |
| --- | --- | --- |
| `POST /essay/topic` | 论文模式出题 | `model`、`topic`（方向，可选）、`notebook_ids` |
| `POST /essay/review` | 小论文批改 | `model`、`text`、`topic`、`notebook_ids` |
| `POST /quiz/exam/annotate` | 整卷大题逐句批注 | `model`、`exam_id`、`question_id`、`answer` |
| `POST /v1/chat/completions` | 答疑 / 论文问答 | 新增 `mode`（qa / paper）、`retrieval_query` |

## 七、已知问题与注意事项

1. **判分有波动**：同一篇范例批两次，分别得 66 分和 60 分，差在「语言与规范」一条要点的判定，属于模型判分的波动，后续可在后端优化。
2. **推送尚未完成**：
   - 本机权限防护拦截了推送，需要手动执行；
   - 队友仓库的 `main` 只有一个「Initial commit」，与本仓库历史无关，推到 `main` 需强推覆盖，建议先和她确认，或推到新分支再合并；
   - 该仓库是**公开的**，推送后后端代码、文档和 `book1.md`（教材正文）都会公开，教材版权需确认。
3. **iCloud 冲突副本**：项目放在 iCloud 同步的桌面上，批量替换文件时会生成「文件名 2」副本（本次已清理），建议把项目移出 iCloud 同步目录。
4. **沿用的既有问题**：队友代码中原有的 lint 问题未改动；对话单条消息上限 2 万字，论文模式附件过大会提示删减。

## 八、如何运行

- 在仓库根目录双击 `start.command`（Windows 用 `start.bat`），脚本会拉起：
  - basic-agent：`127.0.0.1:5001`
  - 前端：`127.0.0.1:5173`（浏览器打开这个）
  - OpenNoteBook：页面 `8502` / 接口 `5055`（Docker）
- 当前工作区在 `merge-paper-assistant` 分支，运行的是合并后的版本；需要旧版本请切回 `master`。
